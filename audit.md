## The fix: fact-checker

The fact-checker was the agent at fault: in C-05 it answered check 2 by guessing, because it was never shown the page text. It now works with general checks only; no claim, service or answer is typed into the code.

- **Check 1 (source)** is code: the page must be in the snapshot, its host must be exactly `aws.amazon.com`, and the researcher's `url` and `captured_at` must match that page.
- **Check 2 (quote)** is code: every quote must appear word for word in that page's `body_text`.
- **Check 3 (facts)** splits the claim into its facts and names, for each one, the quote that backs it or "none". Code then confirms each backing quote is one of the researcher's quotes. The rule is still read from `confirm_rule.md`.
- **The verdict** is computed from the three answers: confirmed only if all three are yes, so it can no longer contradict its checks.

During the fix, one intermediate run made the fact-checker too strict: it rejected C-01 because the quote says "operate" where the claim says "running". The instructions now say that facts are backed by meaning, and that word-for-word copying applies to the quotes (check 2), not to the claim's wording. The run above is the one after that correction.
